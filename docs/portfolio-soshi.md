## プロジェクト概要

### muscloop

muscloop は、筋トレを続けたい人のための継続支援アプリです。  
筋トレ初心者が「何をやればいいかわからない」「記録が面倒で続かない」と感じやすい点に注目し、記録、AI 相談、実績、通知をひとつのアプリにまとめました。

- ハッカソン: `SysHack2026`
- 開発期間: 2026/03/17 - 2026/03/31
- チーム人数: 5名
- 受賞: **サイバーエージェント賞**

## 受賞実績

## 自分の担当

私はこのプロジェクトで、**PM 兼バックエンド担当** として開発に関わりました。

主に担当したことは次の通りです。

- API の実装
- フロントエンドとバックエンドの接続
- AI 機能のダミー実装による導線づくり
- 実機での動作確認
- チーム全体の進行管理と優先順位付け

チーム開発では、各メンバーが担当した機能を最後にひとつのアプリとして成立させる必要がありました。  
そのため、自分は個別機能の実装だけでなく、**全体をつなげて完成まで持っていく役割** を意識して動きました。

## 工夫した点

### 1. まず動く形を作ることを優先した

AI 機能は最初から本実装を目指すのではなく、まずはダミーで動く導線を作ることで、フロントとの接続やユーザー体験の確認を先に進めました。  
これにより、開発を止めずにチーム全体の実装を前へ進めることができました。

### 2. 見た目より先にデータの流れを安定させた

フロントとバックエンドをつなぐ場面では、UI の細かい調整よりも、保存・取得・反映が正しくつながることを優先しました。  
その結果、記録やプロフィール、通知設定など、複数画面にまたがる機能の整合性を取りやすくなりました。

### 3. チーム開発で詰まりを減らすことを意識した

短期間の開発では、誰か一人が止まるだけでも全体の進行に影響します。  
そこで、各メンバーの進捗や詰まりを把握しながら、どこまで実装するか、どこを後回しにするかを整理して進めました。

## 苦労したことと解決

### コンフリクト対応

複数人が近い箇所を同時に触る場面があり、Git のコンフリクト対応に苦労しました。  
原因は、似たタイミングで似た作業が重なっていたことでした。

そこで、担当範囲をできるだけ明確に分け直し、同時に編集する箇所を減らすようにしました。  
この経験から、Git の操作だけでなく、**タスクの切り方そのものが重要** だと学びました。

### 環境差分による起動トラブル

メンバーごとに開発環境が異なり、同じ手順でもうまく起動できないことがありました。  
そのため、接続確認や起動確認を細かく行い、チーム全体で動かせる状態に近づけることを意識しました。

### 文字化けや表示崩れ

開発中に文字化けや表示崩れが発生し、起動や動作確認に影響が出ることがありました。  
こうした場面では、すぐ見た目だけを直すのではなく、まず「何がダメそうか」を整理し、動作に必要な部分から優先して安定させるように進めました。

## 学んだこと

この開発を通して、次のことを学びました。

- アプリを完成まで持っていくためには、実装だけでなく進行管理も重要であること
- バックエンド API を作るだけでなく、フロントとつながって初めて価値になること
- チーム開発では Git の知識とタスク分担の設計がどちらも大切であること
- 初めて触る技術でも、まず小さく動かしながら進めれば形にできること
